Make room for clarity.

Readable text makes the interface useful.

Normal text: AA ≥ 4.5, AAA ≥ 7. Large text: AA ≥ 3 (24 px regular or about 18.67 px bold). Essential UI boundaries/icons: ≥ 3 against adjacent colors. Rounded display values never decide the result.

A small system. Clear decisions.

Use this reference as a starting point, then validate your actual content, devices, states, and audience.

01 / SELECT A FAMILY

Choose atmosphere, then assign roles.

Use one family for the app’s structural surfaces and primary action. Reserve additional hues for meaningful status or data. Build with canvas, surface, text, primary, and onPrimary tokens instead of raw hex in individual components.

02 / RECIPE, NOT REVERSAL

Dark mode has its own hierarchy.

Start with a dark canvas, gently lifted surfaces, and lighter action colors with dark labels. Keep body text softer than pure white when contrast allows. Do not invert every source color or reuse the light button label automatically.

03 / ACCESSIBLE RELATIONSHIPS

Check every neighboring pair.

Target 4.5:1 for ordinary text, 7:1 for extra resilience, and 3:1 for essential UI boundaries and large text. Test hover, pressed, selected, error, and focus states. Decorative separators do not need to masquerade as control boundaries.

04 / COLOR HAS BACKUP

Meaning survives without hue.

Use an error message beside the field, a checkmark for completion, labels on charts, and a visible selected state. Underline inline links. Keep keyboard focus visible and unobscured. A two-color focus treatment can help across mixed surfaces.

05 / PRACTICAL TYPE

Make the small text work first.

Begin app body text around 16 px / 24 px; use 14 px sparingly for secondary UI and 12 px for short metadata. Give headings a tighter line-height. These are design starting points, not accessibility thresholds. Respect zoom and text-size preferences.

06 / READY TO SHIP

Test the actual interface.

Check at 200% zoom and narrow widths, with keyboard-only use, long translations, reduced motion, and relevant assistive technology. Validate loading, empty, disabled, errors, and destructive actions. A ratio alone cannot establish WCAG conformance.

Six typography directionsSame interface · different character
Suggested starting scale: Display 48/56 · H1 36/44 · H2 28/36 · H3 22/30 · Body 16/24 · Label 14/20 · Metadata 12/18. Use 400 for body, 500–600 for labels, and 600–700 for emphasis. Keep line length around 45–75 characters for long prose; test real scripts and content. Compact preview text is scaled for the specimen, not a recommended mobile production size.
